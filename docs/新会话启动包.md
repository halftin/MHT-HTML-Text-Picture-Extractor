### 3.1 在打包机上产出 native EXE（唯一的实质待办）

唯一前置：**装 MSVC**（VS 2022 Build Tools 17.6+，勾「使用 C++ 的桌面开发」）。
命令与背景见 `docs/handoff/H34.md` 与 `CLAUDE.md` 的「native 打包现状」。

```bat
build-native.cmd --prepare-only   :: 先验环境（不依赖 MSVC，约 12 秒）
build-native.cmd                  :: 完整构建 -> dist\MhtExtractor.exe + 12 个 DLL
```

**给智能体的实时反馈契约**（本项已实现并实测）：每次构建在 `logs/` 下产出三件套
（`native-build-<stamp>.log` / `.steps.tsv` / `.report.json`），全过程实时 tee；
跟踪用 `Get-Content logs\native-build-*.log -Wait -Tail 50`。
字段含义见《基于graalvm的…打包工作流程.md》§6.1。

## 五、⚠️ 已知失败与缺陷（**不要误判为重构引入**）

### 5.1 曾经"恒有 1 个失败"的那条 —— ✅ **已修复**

`LayerBTest` 的"无 JavaFX 应不可加载"断言，根因是 `pom.xml` 的 `headless-layer-b` 执行
**无法真正剔除 JavaFX**，要同时满足两条：① `argLine` 把 boot layer 限定 `java.se`（JDK 模块层）；
② `classpathDependencyExcludes` 剔 jar（classpath），**且排除坐标必须带 classifier 与不带 classifier
各写一遍**。现 `mvn test` 两个执行全绿（406/0 + 53/0）。

### 5.2 登记未修（择机处理，均不影响产物正确性）

| 缺陷 | 位置 | 影响 |
|---|---|---|
| 业务层仍在产"已解析文案" | `ImageExtractor` 经 `I18n.get` 产 warning 文案 → 写入 `PreviewCacheMeta.warnings` | 缓存内警告语言取决于预览时 locale；彻底修需业务层产码值，会触及缓存 schema |
| `AD_KEYWORDS` 硬编码 | `ImageExtractor` | 若参数化，**必须同步加入 `imageExtractionFingerprint()`**，否则预览缓存串味 |
| 22/105 个 java 文件在工作区是 CRLF | 全仓库 | 与 `.gitattributes` 的 `*.java text eol=lf` 不符；因 `eol` 规则在 `git add` 时规范化，**仓库内存储不受影响**。一次性修法 `git add --renormalize .` |
| `.claude-work/*.ps1` 全部是 LF-only | 本地（已被 gitignore） | 见 §6.2 陷阱 #11 —— **可能正在静默丢哈希表键**，建议转 CRLF |

### 6.2 陷阱速查（踩过的）

| # | 陷阱 | 规避 |
|---|---|---|
| 1 | 会话权限非完全权限 → 所有子进程 `0xC0000142` | 用 `danger-full-access` |
| 2 | `mvn` 不在 PATH | 用 wrapper + 指定 `JAVA_HOME` 为 NIK |
| 3 | `mvn javafx:run -Dtest.mode=true` **不传系统属性** | 直接起 `java` |
| 4 | `mvn -q test` 吞 surefire 摘要 | 看摘要时不要加 `-q` |
| 5 | git 身份未配置 | 内联 `-c user.name/email`，**勿** `git config` |
| 6 | **别往 `src/main/resources` 放临时文件** | 会被打进 jar（真发生过 `.bak` 事故） |
| 7 | 行号跨会话漂移 | 引用前 `grep -n` 复核 |
| 8 | **"PowerShell 数行比 Java 少"不是换行问题，是编码** | PS 5.1 `Get-Content` 不带 `-Encoding` 时按 GBK 读 UTF-8 无 BOM 文件，DBCS 回退**吞掉"行尾是中文"那行的换行符**。实测同一文件：默认 **4277** vs `-Encoding UTF8`/`ReadAllLines` = **4443**。数行一律显式 UTF-8 |
| 9 | 只有 PowerShell 5.1（无 pwsh 7） | `$args` 是自动变量（别赋值）；`-Dfoo=bar` 会被解析坏（用参数数组 `@(...)`）；写无 BOM UTF-8 用 `[System.IO.File]::WriteAllText` |
| 10 | 驱动本机 Claude CLI | 直连原生 exe `%APPDATA%\npm\node_modules\@anthropic-ai\claude-code\bin\claude.exe`，提示词走 stdin 并 `end()`；**不要** `shell:true` |
| 11 | 🚨 **PS 5.1 在 LF-only 的 `.ps1` 里会静默丢弃哈希表字面量中「注释行之后」的键** | 不报错、不警告（实测 `keys = x,z` vs CRLF 的 `x,y,z`）。`.gitattributes` 本就规定 `*.ps1 eol=crlf` —— **别违反**。曾导致报告里 `steps` 字段凭空消失 |
| 12 | 🚨 **`endlocal` 会丢弃 `setlocal` 内定义的变量** | 批处理末尾写成 `endlocal & exit /b %FINAL_RC%`（整行先展开再执行），否则退出码恒为 0 |
| 13 | 🚨 **日志要能被别人"边写边读"** | 写方 `FileStream(..., FileShare.ReadWrite)`；读方用 `Get-Content` 或同共享模式。**`File.ReadAllText` 会失败**（它用 `FileShare.Read`） |
| 14 | `Select-String` **默认大小写不敏感** | 判定"零命中"类结论时必须 `-CaseSensitive`（曾把 `displayItems.` 算成 `items.`） |

## 七、验证纪律（本项目最重要的工程约定）

**执行方（人或 agent）的自述不能作为验收依据。** 每条结论用**不同手段**独立复验。已验证有效的手段：

| 手段 | 曾发现的问题 |
|---|---|
| 直接聚合 `target/surefire-reports/*.txt`（不读执行方日志） | 多次校正基线 |
| **独立 diff 比对**（跑两轮后 `git diff --no-index` 比 SHA-256） | 证明缓存复用无字节偏差 |
| 自写探针直连生产路径 | 证明缓存 schema 与命中判定正确 |
| **方法/字段级存量对账** | 证明元数据去重没丢条目 |
| **包围语句分析**（向上回溯判断是否 log/注释/测试） | 证明无 UI 泄漏 |
| `git diff --numstat` 看增删行数 | 发现合并脚本**重排整文件**（−606 行） |
| 字节码/常量池扫描（而非 grep import） | 发现全限定名引用可绕过 import 扫描 |
| **变异测试**（把被测行为改坏，确认断言会红） | 证明新断言真有强度 |

**并且：验证脚本自身也可能是错的。** 本项目已多次被自己的验证脚本误导——
`mvn -q` 吞摘要（误判 0 测试）；正则 `[,)]` 漏掉分号结尾的枚举常量；`$null -eq $int` 不可靠；
标记审计"取行内最后一个标识符"→ 假成员名；漏 `MainController.ITEM_VIEW` 这种访问形式 → 假阳性；
`Select-String` 大小写不敏感 → 假命中；`Get-Content` GBK 误读 → 行数错 166。
**对"不一致"要再核一遍再下结论，并先拿一个"已知非零"的样本给扫描器做对照。**
