### E5 的具体目标（实测证据）

:2214  createPreviewCell()          533 行   ← 列表单元格构造 + 拖拽 + 渲染内联

## 五、⚠️ 已知失败与缺陷（不要误判为重构引入）

### 5.1 `mvn test` 有 1 个已知失败

**失败测试**：`LayerBTest.runsWithoutUiFrameworkOnClasspathWhenHeadlessExecutionIsActive:218`
**现象**：`headless 执行下不应能加载 javafx.application.Platform —— 说明 UI 框架仍在 classpath 上`

**根因（两层，第二层决定性）**：
1. `pom.xml` 的 `headless-layer-b` 执行用 `classpathDependencyExcludes`，但写的坐标是**无 classifier** 的 `org.openjfx:javafx-controls`，而实际依赖带 **classifier `win`**（并带出无 classifier 的传递变体）→ **一个都没匹配上**
2. **Liberica `Full` JDK 把 JavaFX 内置为 JDK 运行时模块**（`javafx.base@25.0.3` … 共 7 个，见 `<JDK>/jmods/`）。`classpathDependencyExcludes` 只能剔 Maven 依赖，**剔不掉 JDK 模块**

**实测证据**：剔除 classpath 上全部 openjfx jar 后，探针 `Class.forName("javafx.application.Platform")` **仍成功** → 即"无 JavaFX classpath"在本机**物理不可达**。

**修法三选一**：
- ① 断言降级为 `assumeTrue` + 明确标注"本机不可验证"（最诚实，代价是失去该证据）
- ② **用不含 JavaFX 的 JDK**（Liberica `Standard`/`Lite` 或 Temurin）执行该 surefire execution（**保留证明力，推荐**）
- ③ 固化为手工脚本 + 证据留档

**并且**：无论选哪个，都要**修正或删除** `classpathDependencyExcludes` 的错误坐标，以免持续误导。

### 5.2 已登记未修缺陷（择机处理）

| 缺陷 | 位置 | 影响 |
|---|---|---|
| **纯 Data URI 的 MHT 永远提取不到图片** | `ImageBatchProcessor` 的"无图片内容"快速跳过（`cidMap` 与 `locationDataMap` 均空 → SKIPPED） | **真产品缺陷**：有 Data URI 图却报"跳过：无图片内容"。修它会改变产物基线，须配套更新基线 |
| 业务层仍产"已解析文案" | `ImageExtractor` 经 `I18n.get` 产 warning → 写入 `PreviewCacheMeta.warnings` | 缓存内警告语言取决于预览时 locale；彻底修需业务层产码值，会触及缓存 schema（`FORMAT_VERSION`） |
| `AD_KEYWORDS` 硬编码 | `ImageExtractor` | 若参数化，**必须同步加入 `imageExtractionFingerprint()`**，否则预览缓存串味 |
| `BrowserLauncher` 包归属 | `gui.util`（零 JavaFX） | 见 §三 步骤 4 |
| `reflect-config.json` 与统一元数据并存且不一致 | `src/main/resources/META-INF/native-image/com.mhtextractor/` | 建议确认后删旧留新（native-image 对同 type 取并集） |

## 七、验证纪律（本项目最重要的工程约定）

**执行方（人或 agent）的自述不能作为验收依据。** 每条结论用**不同手段**独立复验。已验证有效的手段：

| 手段 | 曾发现的问题 |
|---|---|
| 直接聚合 `target/surefire-reports/*.txt`（不读执行方日志） | 多次校正基线 |
| **独立 diff 比对**（跑两轮后 `git diff --no-index` 比 SHA-256） | 证明缓存复用无字节偏差 |
| 自写探针直连生产路径 | 证明缓存 schema 与命中判定正确 |
| **方法/字段级存量对账** | 证明元数据去重没丢条目 |
| **包围语句分析**（向上回溯判断是否 log/注释/测试） | 证明无 UI 泄漏 |
| `git diff --numstat` 看增删行数 | 发现合并脚本**重排整文件**（−606 行） |
| 字节码/常量池扫描（而非 grep import） | 发现全限定名引用可绕过 import 扫描 |

**并且：验证脚本自身也可能是错的。** 本项目三次被自己的验证脚本误导——`mvn -q` 吞摘要（误判 0 测试）；
正则 `[,)]` 漏掉分号结尾的枚举常量（误判"少一个"）；`$null -eq $int` 不可靠（误判"全部未完成"）。
**对"不一致"要再核一遍再下结论。**
