## 二、新会话会用到的关键事实（速查）

### 2.1 当前基线

| 指标 | 值 |
|---|---|
| 单测 | **304 / 24 类 / 0 失败** |
| GUI 自动化 | **zh 30/0、en 30/0** |
| 回滚点 | `8ec7058`（另有标签 `pre-i18n-20260926-1015`） |
| 分支 | `2.5-beta` |

### 2.2 必须知道的环境陷阱（完整清单见 `docs/如何调用Claude-CLI.md` §六）

1. 会话权限必须**完全权限**，否则所有子进程 `0xC0000142`
2. `mvn` 不在 PATH → `source .claude-work/env.sh`
3. `mvn javafx:run -Dtest.mode=true` **不传系统属性** → 直接用 `java` + 参数数组
4. `mvn -q test` 吞 surefire 摘要
5. git 身份未配置 → 内联 `-c user.name/email`
6. **不要往 `src/main/resources` 放临时文件**（会被打进 jar）
7. 行号跨会话漂移 → 引用前 `grep -n` 复核

### 2.3 重构的验收标准（来自用户目标）

| 目标 | 可执行验收 |
|---|---|
| ① 架构符合标准、风险点修复 | `项目需求文档.md` §四 的 A/B/C/D 四类问题逐条关闭；`MainController` 行数/方法数显著下降 |
| ② 三层解耦、换 UI 可复用 | 存在零 JavaFX 依赖的应用层包；`ArchitectureTest` 断言依赖闭包无 `javafx.*`；**用桩 UI 适配器跑通完整提取**（`swappingUiAdapterIsPossible`） |
| 全程不退化 | 每步：304+ 单测全绿 + **产物基线 0 差异** + 双 locale GUI 30/0 |

### 2.4 测试策略要点（详见 `docs/重构安全网-测试方法设计.md`）

- **B0 必须先做**：在**动手重构前**建立端到端**产物黄金基线**（否则基线会混入重构后行为）
- 基线只证明"没变"不证明"对"，故必须建立在**已验收版本**上（当前即符合）
- 解耦路径 B1→B9：`ProjectSession` → `ImportService` → `PreviewService` → `ExtractService`
  → `ParamBindingService` → `Undo/Group/ReorderService` → Controller 变瘦适配器
  → 加 `LayerBTest`（纯无头跑通全部功能）→ 加 `ArchitectureTest`
- 现有 30 项 GUI 断言住在 `MainController` 里（§四 A-2 自锁效应），解耦后应**迁出**

### 2.5 解耦的 25 个耦合点（完整表见 `docs/全量链路清单.md` 末节）

最关键的几条：

| # | 耦合点 | 为何关键 |
|---|---|---|
| 3 | `PreviewItem` 把领域数据与 JavaFX 属性同对象 | 不拆这个，业务层无法脱离 JavaFX 数据模型 |
| 6 | 业务层（`BatchProcessor`/`OutputUnitPlanner`/`HtmlExportBuilder`）直接 `I18n.get` 拼文案 | 业务层应产**码值/事件**，文案渲染收口到表现层 |
| 7 | 进度回调经 `javafx.concurrent.Task` 承载 | 应改为可注入的 `ProgressSink`/`CancelToken` 纯接口 |
| 24 | `MainController` 直接 `new` 业务对象（无 DI） | 需简单装配层，GUI 只依赖业务接口 |
| 11 | 缓存清理规则调用点散落 13 处 | 抽 `WorkspaceModel` 统一触发，消除"分支漏调"类 bug |
| 20 | `MainController` 内嵌 1100 行演练/测试代码 | 剥离到独立夹具 |
