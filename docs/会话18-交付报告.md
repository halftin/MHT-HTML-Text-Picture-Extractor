## 四、过程中发现并处置的真实问题

| # | 问题 | 性质 | 处置 |
|---|---|---|---|
| 1 | **纯 Data URI 的 MHT 永远提取不到图片**（`ImageBatchProcessor:324` 快速检查在提取前 SKIPPED） | **产品缺陷** | **登记不修**（R3）；用对照夹具隔离并写入基线 `knownIssues` |
| 2 | **此前"en 30/0"很可能是假绿**：`App` 用 `logs/gui-state.json` 的 locale 覆盖 `I18n`，持久化 locale 优先于 `-Duser.language` | **方法学缺陷** | 修正双 locale 回归入口（种入/恢复 state 文件）；并用 `Group10.zip` 等产物证明 locale 真生效 |
| 3 | **E0.6 原计划"纯搬家"不成立**（需放宽 47 个 private 成员） | 计划偏差 | 上报用户裁决，改为"先 E1 后 E0.6" |
| 4 | **E2.2 原计划"写转发"前提不成立**（撤销分支直接写字段，不走包装方法） | 计划偏差 | 复核后停手，改做真正有收益的收口 + 不变式 |
| 5 | **V1 存在传递依赖漏洞**（`app` 可 import `gui` → 间接依赖 JavaFX，而扫描看不出来） | **架构漏洞** | 新增闭合断言 + 负向验证 |
| 6 | **`WorkspaceModel` 真实缺陷**：拆组后顶层出现重复项 | **代码缺陷** | 定位根因（`parentGroup` 被 restore 重置导致漏删）并修复 |
| 7 | E3-2 的真实范围远大于原估计（触达磁盘缓存 schema） | 计划偏差 | 产出设计文档，**明确不实施** |

## 五、我犯过并修正的错误（记录以备后用）

| # | 错误 | 教训 |
|---|---|---|
| 1 | 把 `x.selected.set(v)` 机械改成字段赋值，**绕过监听器通知** → GUI 断言连锁失败 | 行为语义改写必须走等价入口；**GUI 安全网当场抓住** |
| 2 | 行数守卫**第一次**直接促成更好的设计（粗放写法 +7 行 → 改 `Denial` 形态 +4 行） | 量化护栏能提升设计质量，不只是记数字 |
| 3 | 测试**基线配对错误** ×2（喂 A 夹具却配 B 基线） | **基线测试失败时先怀疑自己选错基线**，再怀疑代码 |
| 4 | 用"活视图"当快照 → `assertEquals(x, x)` **空断言**（永远通过） | **永远通过的断言比没有断言更危险**；它掩盖了真实缺陷 |
| 5 | PowerShell 双引号里的 `\n` 是字面换行 → 注释与代码粘成一行 | 中文/正则脚本一律走**脚本文件**（单引号），不用内联 `-e` |

> 值得注意：本会话中**每一次**"测试失败"都能正确归因 —— 其中相当一部分是**我的测试写错了**，
> 而不是实现错。这说明既有守卫的灵敏度是合适的。
