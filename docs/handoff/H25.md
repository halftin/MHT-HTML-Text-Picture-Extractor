### 1.1 标记语义的边界（本次明确了一条规则）

外迁后有 **12 个 `MainController` 成员**必须从 `private` 放宽为包级（`draggedObject`、`dropHandled`、
`dragActive`、`listAnimating`、`lastDragOverCell`、`imageModeToggle`、`onCellPressed`、
`onCellDoubleClicked`、`onGroupCheckToggled`、`isTextMode`、`unitIndex`、`cancelDrag`）。

**我刻意没有给它们加 `/* test-support */` 标记**，理由：该标记的语义是"**为测试夹具**放宽的封装让步"，
而这 12 处是**生产类之间的同包协作**。混为一谈会让这个计数失去意义。

代价必须讲清楚：**这 12 处封装让步不受 `testSupportSurfaceDoesNotGrow` 约束**。
若日后要约束它们，应另立断言。此事已写入 `ArchitectureTest` 的 javadoc。

标记数因此是 **46 → 44**（下降，因为随单元格外迁带走了若干标记），上限收紧到 44。

## 二、⚠️ 这个过程很长，我犯的错误清单（如实记录）

这次外迁是本项目至今**机械替换最复杂**的一次（涉及跨类引用、可见性、常量归属、静态初始化顺序）。
我按"编译错误 → 修 → 再编译"的循环推进，期间犯了下面这些错。

| # | 错误 | 后果 | 修正 |
|---|---|---|---|
| 1 | 限定正则**连声明行一起改** | `private String itemParamStyle(...)` → `private String ctl.itemParamStyle(...)`，语法崩 | 声明行豁免（`private/public/protected/static/final` 前缀检测） |
| 2 | 误判"单元格不使用 `GROUP_ROW_EDGE_ZONE`" | 实际通过 `ctl.` 使用 | 迁移后按新形态重新核对 |
| 3 | 常量归属判断错误（用"出现次数 ≤1"当"仅声明"） | `CELL_PAD`/`ROW_PAD`/`CHECK_COL_WIDTH` 被误留/误移 | 改为逐个检查**除声明外**的引用 |
| 4 | 常量追加到类末尾 | `GROUP_ROW_SELECTED_STYLE` 引用尚未声明的 `CELL_PAD` → **非法前向引用** | 按依赖拓扑排序常量声明 |
| 5 | 建了两个构造函数 | `PreviewListCell()` 与 `PreviewListCell(MainController)` 并存 → 重复定义 | 删除空壳，保留真正初始化 UI 的那个 |
| 6 | 漏 import（`FontIcon`/`ChangeListener`/`ExtractOutcome`/`Insets`/`DropShadow`/`Image`/`Priority`/`SelectionState`/`Slf4j`） | 逐个"找不到符号" | 按 MainController 的 import 对照补齐 |
| 7 | `handleDrop`/`dropHandled` 方向搞反 | `ctl.handleDrop(e)` 应为本地 `handleDrop(e)`；`dropHandled` 反而必须 `ctl.` | 逐个核实成员真正的归属类 |

**根因**：我一开始把"迁移"当成纯文本替换，但**成员归属（在哪个类里）本身就需要逐个判断**——
有的方法被搬进了单元格、有的留在控制器，而同名成员两边都有（`statusLabel`/`handleDrop`）。
这正是本项目反复记录的教训：**机械替换前必须先把"每个符号属于哪一边"确定下来**。
