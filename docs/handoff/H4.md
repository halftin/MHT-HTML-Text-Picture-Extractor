## ⚠️ 行为变更（R5）
1. **重命名模式撞名从「静默覆盖」改为「失败返回 null」**（`ImageWriter.writeWithoutOverwrite`，rename=true 时 `FileAlreadyExistsException` 直接抛出）。触发场景：重跑提取且目标目录残留上次（未完成）运行的 `00000.ext` 等文件。旧行为静默覆盖，新行为记 error 日志并计入失败数——会话 5 的 `saved == 0` 判定会把它呈现为用户可见失败而非绿成功+文件被换。
2. **fallbackExt 为 null/空时扩展名回退 "jpg"**（`normalizeExt`）：旧行为可能落盘 `photo.null`/`00001.null` 这类垃圾名；新行为 `photo.jpg`。正常调用方（ImageBatchProcessor 传 "jpg"、MainController:4409 传魔数检测结果）不受影响，预览命名不变。
3. **`computeFileName(null 或 data==null, ...)` 返回 `"unnamed.<ext>"`**：旧行为对 null imageData 抛 NPE（saveImage 有守卫所以生产路径不可达）；仅影响 GUI 直接调用（MainController:4409，传值有效，不受影响）。
4. **Archiver 源目录只有子目录时返回 false + warning**：旧行为产出空 zip 并返回 true（随后源目录被删 → 数据丢失）。会话 5 的 P0-2 修复会检查返回值，新行为下空归档不会触发删源目录。
5. **Archiver 失败（含 close 阶段失败）删除已写出的目标归档文件**：磁盘满等场景不再留下「看似正常但损坏」的半截 zip/cbz。
