## 一、做了什么

### 1.1 手法

把 `FeatureExercise` 里对 `MainController` 的 **`mc.<@FXML字段>` 直接引用（125 处）**
改为按 `fx:id` 定位节点：

```java
// 之前（要求字段必须保持包级可见 → 必须带 test-support 标记）
mc.undoButton.fire();

// 之后（字段可收回 private）
undoButton().fire();
```

宿主放在 **`FeatureExercise` 内**（**测试源集**，不占 `MainController` 的 4985 行零余量）：

```java
private javafx.scene.Node node(String fxId)              // 找不到即抛异常，不静默返回 null
private <T> T node(String fxId, Class<T> type)            // 类型校验
private javafx.scene.control.Button undoButton() { ... }   // 16 个类型化访问器
```

于是 **16 个 `@FXML` 字段**不再需要包级可见性，全部 `private` 化并摘标记。

## 二、⚠️ 本阶段我犯了两个错（都已修正，记录以免重犯）

### 2.1 `mc.getScene()` 不存在

`MainController` 是**普通 FXML 控制器**（`public class MainController`），**不是 `Node`**，
因此没有 `getScene()`。编译直接失败（`找不到符号`）。

**修法**：借一个必然挂进场景图的控件取 Scene —— `mc.fileListView.getScene()`。
`fileListView` 本身无标记（是 `@FXML ListView<Object> fileListView;`），属既有包级可见。

### 2.2 脚本生成了"无类型访问器"与"类型化访问器"两套，且调用点用了错的那套

第一版迁移脚本把调用点改成了 `node("undoButton").fire()` —— 但 `node(String)` 的返回类型是
`javafx.scene.Node`，**没有 `fire()` / `setSelected()` / `setText()` 等方法**，于是约 100 处编译失败。

| 生成物 | 问题 |
|---|---|
| 调用点用 `node("x").method()` | `node(String)` 返回 `Node`，控件方法不存在 |
| 我同时生成了 16 个类型化访问器 `x()` | 生成了却没用上 |

**修法**：脚本二（`.claude-work/s1c-fix-typed.js`）把 125 处 `node("x").` 改写为 `x().`，
并断言"零残留 + 每个访问器恰好出现一次"。改后一次编译通过。

> **教训**：机械替换必须先确定**替换后表达式的静态类型**是否仍支持原有的方法调用。
> 我验证了"节点能被 lookup 找到"，却没验证"lookup 的返回类型够不够用"——这是两个不同的问题。

### 2.3 一个虚惊（记录以免误判）

替换后用 PowerShell `Get-Content` 看文件，中文全是乱码，一度以为编码被我搞坏了。
**字节级核对后确认：文件是合法 UTF-8**，乱码只是 **PS 5.1 控制台按 GBK 渲染**的结果；
用 `read` 工具（按 UTF-8 解码）看完全正常。
> 又一次印证：**"看起来不对"要先做字节级复核再下结论**。

### 剩余 46 处的性质（**不能**用 `lookup` 解决）

| 类别 | 代表（引用次数） | 难度 |

| 状态字段 | `items`(11)、`textParamsCache`(22)、`imageParamsCache`(14)、`parseToken`(4)、`lastExtractStats`(4)、`undoManager`(4)、`running`(3)、`imageLoadActive`(2)、`importPending`(2)、`importDragDepth`(1) … | 高：属"读状态做断言" |

| 内部类 | `PreviewListCell`（1） | 高：`findCell` 返回它 |

要再降，只有两条路：①在 `app` 层或 `gui` 层设计一个**显式的测试支撑 API**（而不是"整批放宽 private"）；

两者都是独立且明显更难的工作，**建议排在步骤 2（预览编排搬入 app）之后评估** ——
