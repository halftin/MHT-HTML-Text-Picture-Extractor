## 六之三、E0 期间发现的三个实质问题（均已处置）

### 1. ★ 新缺陷：纯 Data URI 的 MHT 永远提取不到图片

- **位置**：`ImageBatchProcessor.java:324` —— `if (parsed.getCidMap().isEmpty() && parsed.getLocationDataMap().isEmpty())` → 直接 SKIPPED
- **隔离证据**（对照夹具，非推断）：

  | 夹具 | 内容 | 产物 |
  |---|---|---|
  | `data-uri.mht` | **只有** 2 张 Data URI，无 MIME 图片 part | **0 个产物**，outcome=SKIPPED |
  | `data-uri-mixed.mht` | 1 张 cid 图 + 2 张 Data URI | **3 个产物**：`img001.jpg`、`image_1.png`、`image_2.gif` |

  两者对照证明：问题在**前置快速检查**，**不在** `ImageExtractor.extractDataUriImages`（该代码本身可用）。
- **与既有文档冲突**：`docs/全量功能清单.md` §F 把"Data URI 提取"标为可用功能。
- **处置**：按 R3 **登记不修**（登记表 #17）。修它会改变产物基线，与"重构零行为变更"的验收口径冲突。
  基线 `image-data-uri.{zh,en}.json` 带 `knownIssues` 明确标注"**这是缺陷，不是期望值**"。

### 2. ★ 方法学缺陷：此前"en 30/0"很可能是**假绿**

- **机制**：`App.start:36-42` 在 `FXMLLoader.load()` **之前**用 `logs/gui-state.json` 的 `"locale"` 覆盖 `I18n`
  → **持久化 locale 优先于 `-Duser.language`**。而该文件当时写着 `"locale":"zh_CN"`。
- **后果**：`run-test-mode -Duser.language=en -Duser.country=US`（会话 17 文档 §五 的做法）实际渲染的是**中文界面**，
  断言"30/30 通过"却完全没验证英文路径。
- **修正**：改为**运行前种入/删除** `gui-state.json` 的 locale（`.claude-work/seed-gui-state.js`），运行后恢复。
- **验证 locale 真的生效**（不采信计数器）：same-fixture en 运行的会话目录出现 `Group10.zip`（zh 为 `组…`），
  即 `core.groupDefault` 的 en 值 `Group` 确实被使用。
- **遗留（登记）**：GUI 自动化的 30 项断言是 locale 无关的**控制状态**断言，
  **不校验界面文案语言**。真正的"英文界面无中文残留"仍属 I2 人工点验范畴（阶段 D 遗留）。
  另有：应用**日志**文案（`log.info` 等）本来就不属于 UI 文案（会话 15 有意不动），英文运行下日志仍为中文，这是设计使然、非缺陷。

### 3. 行数口径陷阱（已写入架构测试注释）

`MainController.java` 实测 **6111** 行，但**不同工具数出的结果不同**：
PowerShell `(Get-Content f).Count` = **5882**，Node（按 Java 规则）= **6111**，Java `Files.readAllLines` = **6111**。
原因：文件为纯 `LF` 换行，`Get-Content` 的分行/编码处理与之不一致。
→ 架构测试的 `MAIN_CONTROLLER_MAX_LINES` **只能与 `Files.readAllLines` 口径比较**，
不要拿 PowerShell 的数字去改它（会立刻假失败或假通过）。
另：`docs/新会话交接总纲.md` 记的"约 6100 行"**是对的**，会话 18 早先汇报的 5882 是 PowerShell 口径的误读，此处更正。

### 4. 附带修正：架构白名单最初不完整（本测试自身抓出来的）

只凭 `grep 'import javafx'` 得出的泄漏点是 2 个，**实际是 4 个** ——
`DropResolver` 与 `OutputUnitPlanner` **没有** import javafx，而是在方法签名里用了**全限定名**
`javafx.collections.ObservableList`。
这正是"扫字节码而非扫 import"的价值：**源码 grep 会漏，常量池不会**。
（该发现同时说明会话 17 链路清单的耦合点 #2 覆盖面偏窄：`GroupStructure` 之外还有两个 util 类同样依赖 `ObservableList`。）
