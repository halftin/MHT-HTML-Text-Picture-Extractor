## 新发现（未修，留待后续）
1. **ImageSource 无需扩展**（任务 8.4 预留的「更窄接口」判断）：现有 `size()/get(int)` 形态 + 「每次 get(i) 只读当前这张、不缓存已读字节」即可达成「任意时刻内存至多一张全尺寸图」的目标，故**未改 ImageSource 签名**（会话 6 的两个调用方不受影响）。会话 10 直接 `new DirectoryImageSource(meta, cacheDir)` 换实现即可。
2. `listKeys()` 的 key 是**从各目录 meta.json 重建**的（哈希单向、目录名不可反推）；无 .complete 的目录被跳过。若将来需要「按文件路径反查缓存目录」，走 `compute(...) + dirFor(...)` 而非 listKeys。
3. `write` 的提交顺序：tmp 全部写完后 → 删旧缓存 → `Files.move`（同根目录内改名，天然原子；未用 ATOMIC_MOVE，部分 FS 会抛 AtomicMoveNotSupportedException）→ 最后写 .complete。**写入失败时旧缓存保持可用**（旧目录在提交前一刻才删）。
4. 异常语义约定：`load` 对 meta.json 损坏/不可读**抛 IOException**（显式失败）；对图片文件缺失返回 empty（视为未命中并 log.warn）。注意：`.complete` 存在但 meta 损坏的目录**不会被 cleanupOrphans 清理**（它只删无 .complete 与 .tmp 的）——此状态会残留到下次同 key 写入（write 会先删旧目录）或 deleteAll，会话 9 如需可自行兜底。
5. `toDirName` 取**全 64 位** hex（HtmlExportBuilder.cacheKey 只取前 16 位）：无碰撞顾虑，与 AppConfig 指纹的 64 位风格一致。

**meta.json 最终字段结构**（Jackson 序列化 `PreviewCacheMeta`，缩进输出、未知字段忽略）：

```json
{
  "formatVersion" : 1,
  "source" : { "absolutePath" : "D:\\...\\a.mht", "size" : 123456, "mtime" : 1758700000000 },
  "paramFingerprint" : "<64 位 hex>",
  "imageMode" : true,
  "images" : [ {
    "file" : "images/0001.png",
    "sourceId" : "cid:img001",
    "originalName" : "封面.png",
    "detectedExt" : "png",
    "warnings" : [ ]
  } ],
  "warnings" : [ "w1" ]
}
```

**toDirName 算法**：`absolutePath + "|" + size + "|" + mtime + "|" + paramFingerprint + "|v" + formatVersion` 的 UTF-8 字节 → SHA-256 → 全 64 位小写 hex（HexFormat）。`HtmlExportBuilder.cacheKey` 同构（它只取前 16 位）。

**命中判定逻辑（load）**：`dir 存在` ∧ `.complete 存在` ∧ `meta.matches(key)`（formatVersion + paramFingerprint + source 三要素全等，P9）∧ `全部 images[].file 为常规文件` → 命中；任一不满足 → empty。meta 解析失败 → 抛 IOException。

**给会话 9 的落地提示**：
