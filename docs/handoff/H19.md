## 一、做了什么

### 1.1 修复 `headless-layer-b` 执行（`pom.xml`）

```xml
<argLine>--limit-modules java.se</argLine>
<classpathDependencyExcludes>
    <!-- 无 classifier 四条（原有，保留） -->
    <classpathDependencyExclude>org.openjfx:javafx-controls</classpathDependencyExclude>
    ...
    <!-- 新增：带 classifier win 四条 -->
    <classpathDependencyExclude>org.openjfx:javafx-controls:win</classpathDependencyExclude>
    ...
</classpathDependencyExcludes>
```

### 1.2 ⚠️ 修正了此前文档里的**根因结论**（重要，勿再沿用旧说法）

旧结论（`CLAUDE.md`、两份 GraalVM 文档、启动包 §5.1）说：

> "无 JavaFX classpath"在本机**物理不可达**，因为 `classpathDependencyExcludes` 剔不掉 JDK 模块。

**这个结论是错的**（或者说只在"不动其他条件"时成立）。实测真相是**两个独立条件，必须同时满足**：

| 条件 | 手段 | 管什么 | 不做会怎样 |
|---|---|---|---|
| **A** | `argLine` = 把 boot layer 限定在 `java.se` | **JDK 模块层**：Liberica Full 把 JavaFX 内置为 7 个 JDK 运行时模块 | 即使 classpath 干净，JavaFX 仍能从 `jrt:` 加载 |
| **B** | `classpathDependencyExcludes` 剔干净 jar | **classpath（未命名模块）** | 即使模块层没有 JavaFX，classpath 上的同名类仍可被加载 |

**决定性反例（本会话实测，推翻了旧结论）**：

```
cp 只含本探针:                    limit 前 LOADED      limit 后 ABSENT
cp 含 javafx-base-win.jar:        limit 前 LOADED      limit 后 LOADED  ← limit 对 classpath 无效
```

即 **`--limit-modules` 只约束模块层，不会屏蔽 classpath 上的 jar**。旧文档"剔除 classpath 全部 openjfx jar 后 `Class.forName` 仍成功"的记录是**真的**，但它只证明了条件 A 缺失时 B 单独无效，**不能推出"物理不可达"**。

### 1.3 修正了排除坐标（旧写法部分失效）

- `classpathDependencyExcludes` 只排除与给出的 `groupId:artifactId` **完全相等**的坐标，**不做前缀匹配**。
- 旧写法只有无 classifier 的四条，而实际依赖是 `org.openjfx:javafx-*:win`，**另带出无 classifier 的传递变体**。
- 用 `mvn -X` 核对 forked classpath 证实：修复前**两种 jar 同时在场**（`javafx-base-25.0.3.jar` 与 `javafx-base-25.0.3-win.jar`）。所以旧写法**只剔掉了传递变体，放过了真正的 `win` jar**。
- 修复后核对：forked classpath 上 `openjfx/**.jar` **0 条**。

### 1.4 `LayerBTest` 本身**一字未改**

原断言（`:218`）"headless 执行下不应能加载 JavaFX"保持原样，证明力**完整保留**（不是降级成 `assumeTrue`）。
仅 `pom.xml` 里一句注释从"不在 classpath 上"改为"不可加载"，因为新机制下"不在 classpath 上"不再精确。

## 四、踩过的坑（记录，避免重复）

| # | 坑 | 结论 |
|---|---|---|
| 1 | 把 `--limit-modules` 当 JVM 选项，用 `JAVA_TOOL_OPTIONS` 传 | ❌ 报 `Unrecognized option`。它是 **launcher 选项**，只能出现在 `java` 之后的**命令行**位置；surefire 里只能走 `<argLine>` |
| 2 | 以为 `argLine` 一定能生效 | ❌ 第一次改完仍失败 —— 因为**条件 B 没做完**（classpath 上仍有 `win` jar）。**两个条件缺一不可**，这正是修复的关键 |
| 3 | 以为把注释里的 `--limit-modules` 换个写法就行 | ❌ XML 注释禁止任何连续两个短横线，**中文破折号 `——` 也算**，会直接 `Non-parseable POM`。pom 注释里已注明"严禁连续两个短横线，选项名写在元素里不复述" |
| 4 | 用 PowerShell 直写 `java ... -Dtest.mode=true` | ❌ `-Duser.language=zh` 被 PS 拆成 `/language=zh` → `ClassNotFoundException: /language=zh`。**必须用参数数组 `@(...)` 传** |
| 5 | 用 `-Dtest=A,B` 做选择性验证 | ⚠️ 该 `-Dtest` 会被**默认执行与 headless 执行同时套用**，导致聚合口径出现 12/44/11 的歧义（**测量假象，非代码问题**）。要统计口径就**跑全量**，别用选择性过滤 |
| 6 | 验证脚本输出中文 | ❌ PS 5.1 控制台编码把中文糊掉（连 `F=0`/`E=0` 都看不见）。独立复验脚本已改为 **ASCII-only 输出** |
