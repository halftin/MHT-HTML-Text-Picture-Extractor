## `I18n` 完整 public API（`com.mhtextractor.i18n`）
```java
public static String get(String key, Object... args)   // 具名占位符替换；缺键返回 !key! 并 log.error
public static void setLocale(Locale locale)            // null = 跟随系统默认；目标 bundle 缺失回退 zh_CN
public static Locale currentLocale()
public static ResourceBundle bundle()                  // 会话 15 FXMLLoader 注入用（loader.setResources）
public static Locale parseLocale(String s)             // "zh_CN"/"en_US"/"zh-CN"/"zh"；空白或非法 → null
```
**禁止**业务代码直接 `ResourceBundle.getBundle`（架构设计 §三）。

## 占位符语法与缺键策略的实现方式
- **具名占位符** `{name}`（正则 `\{(\w+)\}`），不用 MessageFormat 数字索引（翻译易错位 + 单引号转义陷阱，§3.1）。
- **args 形式**（javadoc 已写明）：varargs 为**交替键值对**——`I18n.get("extract.groupFileCount", "group", "组1", "count", 3)`。
  键非 String 的项忽略；个数为奇数 → log.warn 并忽略末尾键。
- **缺键**（§3.2 严格照做）：`MissingResourceException` → `log.error("i18n 缺键：{}", key)` + 返回 `"!" + key + "!"`；不返回 null、不原样返回键名。
- **占位符缺参**：不静默——`{name}` 原样保留 + log.warn（列出缺失占位符）。
- 替换实现：`Matcher.appendReplacement` + `Matcher.quoteReplacement`（参数值含 `$`/`\` 时安全）。
- 线程安全：`bundle`/`current` 均 volatile；`setLocale` 语义为"启动时一次性调用"。
- 缺 bundle 回退：`ResourceBundle.getBundle("i18n/messages", target)` 失败 → 回退 zh_CN（zh 值 = 现有中文原文，老用户零影响）。
- 实测（JDK 25）：UTF-8 中文 properties 直写可读（JEP 226，无需 \uXXXX 转义）；`\n` 转义正确；值尾随空格实际保留，但 bundle 仍按 `\ ` 防御性转义写出。

## ⚠️ 行为变更（R5）
1. **新增**：启动时多读一次 `logs/gui-state.json`（`App.start` 调 `GuiStateManager.load()`；`MainController.restoreGuiState` 仍各读各的，两次均为只读，无冲突、开销可忽略）。
2. **已知限制（会话 14 必须补）**：`MainController.saveGuiState()` 新建 `GuiState` 不携带 locale ——
   用户在 GUI 触发任何状态保存（改目录/切模式）后，gui-state.json 的 `locale` 会被回写为 null。
   当前会话内 locale 只能通过**手工编辑 gui-state.json**（加 `"locale" : "en_US"`）或 `-Duser.language=en` 设置。
   会话 14 落地时需在 `saveGuiState` 补回写（或由 MainController 持有当前 locale）。
3. **未变**：zh locale 下窗口标题仍为「MHT 资源提取器」（app.title 的 zh 值 = 原文）；其余全部 UI 文案零改动；core/processor/output 零改动。
4. `locale` 值无效（如 `"garbage"`）→ `parseLocale` 返回 null → 跟随系统默认，不抛异常。
