## 一、为什么先拆这一块

`BrowserLauncher` 的 866 行里有 4 类职责（启动包要求拆 4 类）。我先选**源码视图页生成**，因为它：

1. **是叶子**：它只做"HTML → 带行号/高亮的 HTML"的纯字符串与 IO 处理，
   **完全不依赖**浏览器 exe 探测、进程启动、CDP 协议 —— 拆出去不需要定义任何跨类契约。
   这正是步骤 3（`PreviewListCell` 外迁）最大的难点所在，这里天然不存在。
2. **正是 `I18n` 问题所在**：步骤 5a 暴露的"基础设施层产本地化文案"就在这块（见 H26 §二）。

拆出的成员（原行号）：

| 成员 | 行数 | 说明 |
|---|---|---|
| `writeSourceViewPage` | 25 | 入口：拼页头 + 样式 |
| `buildSourceViewBody` | 63 | 整篇扫描、按 `\n` 提交行 |
| `writeTag` | 71 | 单标签高亮（标签/属性/属性值） |
| `valueClass` / `isNameChar` / `trimUrl` | 8 / 3 / 5 | 属性值分类与工具 |
| `LineWriter`（嵌套类，含 `escape`） | 76 | 行输出器：跨行 span 闭合/重开 |
| `URL_PATTERN` 常量 | 1 | 由两个成员共用 |

`SOURCE_VIEW_NAME` 常量**一并移入** `SourceViewPage`（它就是这个页面的文件名；
实测 `gui` 侧**没有任何引用**，迁移前它是"只有本类使用"的 public 常量）。

## 二、访问性与调用点

| 项 | 处理 |
|---|---|
| `writeSourceViewPage` | `private static` → **`static`（包级）**，供 `BrowserLauncher` 调用；入口点限定为 `SourceViewPage.writeSourceViewPage(...)` |
| 其余成员 | 保持 `private static`（含 `LineWriter` 内部实现） |

好处是：`I18n` 引用现在**集中在一个 310 行的叶子类里**（原先是藏在 866 行的混合类里），
`ArchitectureTest` 的输出也已明确标出它（`platform/SourceViewPage.java=1`）—— 清理面变小了。

## 三、我在本步犯的错（已修正）

| # | 错误 | 后果 | 修正 |
|---|---|---|---|
| 1 | 计算的块结束行用了 `lines.length - 1` | 截掉了 `BrowserLauncher` 的**类结束大括号**，括号失衡 | 补回 `}` |
| 2 | 生成的 `SourceViewPage` **缺 `@Slf4j` 与类声明** | `-source 21` 报"不支持记录模式"等误导性错误（实为文件结构损坏的连锁反应） | 补 `@Slf4j final class SourceViewPage { private SourceViewPage() {} }` |
| 3 | 用"删最后一个 `}`"修括号失衡 | 把类的结束大括号删掉了 | 手工把结尾结构改对 |

> **教训（与步骤 3 同源）**：跨文件搬代码时，**块边界必须用花括号配平来判定，不能用"总行数减一"这类估算**。
> 估算在文件末尾有注释/空行时就会错，而错误表现为**编译器乱报的语法错误**，很难反推。
