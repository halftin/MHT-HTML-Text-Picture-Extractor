## 一、拆出的内容

| 成员 | 说明 |
|---|---|
| `detectDefaultBrowserExe` | 按序探测：注册表 `UserChoice` → `http` 协议命令 → 常见安装路径 → `where.exe` |
| `isChromium` | 判断 exe 是否 Chromium 系（与探测同属"识别浏览器"职责） |
| `readRegistryValue` / `exeFromRegistryCommand` / `parseCommandExe` | 注册表读取与命令解析 |
| `candidatePaths` / `whereExe` | 常见路径与 `where.exe` 兜底 |
| `decodeConsole` | 控制台输出解码：先 UTF-8 严格解码，失败回退 GBK（中文系统 `reg.exe` 为代码页 GBK） |

**注意**：`isChromium` 在文件里的位置**不与其余探测成员相邻**（它在前、探测块在后），
所以拆成了**两个不连续的区间**分别搬运，而不是当作一个连续块。

### 1.1 访问性

| 方法 | 处理 | 理由 |
|---|---|---|
| `detectDefaultBrowserExe` | → 包级 `static` | `BrowserLauncher` 仍需调用 |
| `isChromium` | → 包级 `static` | `openViewSourceNative` 仍需调用 |
| `decodeConsole` | → 包级 `static` | `killListenerOnPort` 仍需调用 |
| 其余 | 保持 `private` | 只在 `BrowserDetector` 内部使用 |

外部调用点全部加限定：`BrowserDetector.detectDefaultBrowserExe(...)`、`BrowserDetector.isChromium(...)`、
`BrowserDetector.decodeConsole(...)`。

## 二、本步我犯的错（已修正）

| # | 错误 | 后果 | 修正 |
|---|---|---|---|
| 1 | `findLine("boolean isChromium(...)")` **没有从首个成员之后开始找** | 匹配到**调用点**（第 311 行）而非声明（第 402 行之后的区域），算出负长度区间，脚本 ABORT（幸好 ABORT 在写文件之前，未损坏文件） | 明确区分"调用点"与"声明"，并单独处理不连续区间 |
| 2 | 只按外部调用点加限定，漏了 `decodeConsole` 的两处调用 | 编译报"找不到符号" | 改成**枚举所有被搬成员**、逐个扫描两侧文件的未限定调用（而不是靠编译错误逐个发现） |
| 3 | `isChromium`/`decodeConsole` 忘了放宽为包级 | 「private 访问权限」编译错误 | 一并放宽 |

> **教训（第三次同源，已写入 H25/H27）**：跨文件搬代码时，
> ①**块边界必须用花括号配平**判定（本次做对了，未再出现括号失衡）；
> ②**"哪个符号被搬走"必须靠枚举，不能靠编译器逐个报错**去发现 —— 编译器只报第一个撞上的，
> 逐个修会多花好几轮。本次的错误 2 就是没枚举全造成的。
> ③**位置查找要区分"声明"与"调用点"** —— 同名 token 在文件里出现多次时，`indexOf` 语义极易出错。
