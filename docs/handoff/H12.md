## 需求与拍板回顾
缓存目录没有任何磁盘上限（用户明确不要配额/淘汰/LRU）。只要求：缓存目录每新增 10GiB 数据后弹窗提醒一次。
拍板：① 计数口径 = **当前磁盘占用**（非累计写入量——write 是覆盖写，累计量会重复计数重建）；② 每跳一个 10GiB 台阶提醒一次，同台阶不重复，跨多台阶只一次且文本反映当前实际值；③ 非模态弹窗 + 醒目日志；④ 不做配额。

## 实现

### 1. `PreviewCacheStore.totalBytes()`（纯容量查询，无 GUI 概念）
```java
public long totalBytes() throws IOException
```
- **统计口径**：遍历 root 下**全部常规文件**求和。**含 `.tmp` 写入中目录与孤儿残留**——它们同样真实占用磁盘，提醒的是「占用本身」而非「有效缓存量」；不计目录项自身（占比极小）。root 不存在返回 0。
- **并发边界**：写入/删除并发期间的遍历可能抛 IOException（如 NoSuchFileException）——由调用方（checkSizeAlert）降级处理，store 不吞。
- javadoc 已写明口径（文件头注释同步加了目录布局说明不变）。

### 2. `PreviewCacheLifecycle` 台阶状态与判定（规则集中地）
- 常量：`public static final long SIZE_ALERT_STEP_BYTES = 10L * 1024 * 1024 * 1024`（二进制口径 10GiB）。
- 状态字段：`AtomicLong lastReportedStep`（初始 0 = 尚未提醒；**CAS 推进，不用普通 long**）。
- 可注入台阶：新增**包可见**构造器 `PreviewCacheLifecycle(store, stepBytes)`；public 构造器委托它并传默认 10GiB。生产 API 零污染（包外不可见）。
- `setSizeAlertHook(IntConsumer)`：注册回调，**参数 = 已跨越的台阶序号**（默认台阶下 1=10GiB、2=20GiB…）。说明：拍板原文为「回调参数 = GiB 台阶数（10/20/30）」——因可注入小台阶时「GiB 数」对测试无意义，落地为**台阶序号**，MainController 换算 `step × SIZE_ALERT_STEP_BYTES / 1GiB`（默认台阶下 = step×10）后展示，生产行为与拍板完全等价。
- `checkSizeAlert()`（写盘成功后调用）：
  1. `store.totalBytes()` → IOException 时 **log.warn 静默降级，绝不打断预览**；
  2. `currentStep = total / sizeAlertStepBytes`；
  3. `while ((prev = lastReportedStep.get()) < currentStep)` 循环 CAS 抢占：**成功者**才触发提醒（log.warn + hook），失败者直接返回。
- **并发语义**：同台阶并发调用恰一次触发（CAS 单赢家）；并发观察到不同台阶时「谁推进谁提醒」各一次、后到者带更高台阶参数（比只报第一次更符合「文本反映当前实际值」口径）。幂等：已推进过的台阶（含未注册 hook 时）不再补提醒。
- 辅助：`lastObservedTotalBytes()` getter（volatile），供 UI 换算「当前实际 GiB」。

### 3. MainController 接线与 UI
- **hook 注册位置**：`initialize()`（:571 `startupCleanup()` 之后），`previewCacheLifecycle.setSizeAlertHook(this::onSizeAlertStep)`。
- **`checkSizeAlert()` 调用点**：`loadOrWritePreviewCache`（:4772 附近，`store().write(...)` 成功 + 落盘日志之后，`return meta` 之前）。**理由**：该点是全程序唯一「确定刚发生写入」的位置——命中路径不触发（符合「每次写入成功后」口径）；会话 10 的提取复用只读缓存不写，无需检查。该调用位于每项目写锁内：树遍历只延迟**同项目**后续写盘的启动（本就串行），不同项目互不阻塞；写盘路径本身是重路径（解析+提取），多一次遍历占比可忽略。
- **UI 呈现**（`onSizeAlertStep`，在预览后台线程被同步调用）：换算台阶 GiB 与当前实际 GiB → `Platform.runLater(() -> showAlertNonModal(AlertType.INFORMATION, message))`。
- **`showAlertNonModal(AlertType, String)`**：新增私有方法（`alert.show()`，非模态）；**未修改**现有模态 `showAlert`（其它调用点语义不变）。字段 `Alert sizeAlertWindow` 保留窗口引用，上一提醒仍显示时先 `close()` 再弹新，防台阶连续跨越时窗口堆积。
- **提醒文本原文**（弹窗与 log.warn 同义）：
  ```
  预览缓存已占用约 20 GiB，当前实际 21.3 GiB（临时目录：D:\...\mht-extractor-preview）。
  这只是提醒，不影响继续使用；关闭程序会自动清空该缓存。
  ```
  日志：`预览缓存磁盘占用提醒：已超过 20 GiB（当前 21.3 GiB，<root>）。仅提醒、不限制使用；关闭程序将自动清空缓存。`（log.warn，Logback 转发到界面日志区）。

## 测试如何绕过 10GiB 无法真实达成的问题
**包可见构造器注入小台阶**（1024 字节），`checkSizeAlert` 的所有判定路径（CAS/幂等/并发）与生产完全同构，仅常量不同：
- `PreviewCacheStoreTest` +4：`totalBytesSumsImagesAndMeta`（2 张已知大小图片 + meta.json 求和相符，.complete 为空文件不计）、`totalBytesIncludesTmpResidue`（.tmp 残留计入）、`totalBytesZeroWhenRootMissing`、`totalBytesDecreasesAfterDelete`。
- `PreviewCacheLifecycleTest` +7：`sizeAlertStepDefaultIsTenGiB`（锁常量）、`noAlertBelowStep`（未跨不触发）、`alertFiresOnceWithCorrectStepOnCrossingOneStep`（参数=1）、`alertIdempotentWithinSameStep`（同台阶三次调用只一次）、`alertFiresOnceWhenCrossingMultipleSteps`（3500 字节跨 3 台阶 → 恰一次、参数=3）、`concurrentChecksFireOnlyOnce`（16 线程 + CountDownLatch → 恰一次、参数=2）、`crossingWithoutHookAdvancesStepSilently`（未注册 hook 只推进不抛，注册后同台阶不补提醒）。
- 全部 @TempDir 隔离，**绝不触碰真实缓存根**；零 JavaFX。
