## ⚠️ 行为变更（R5）
1. **预览不再把全尺寸图片驻留内存**：原实现 `extractImages` 结果在函数内流转（本就随函数返回回收），新实现落盘后**缩略图改从磁盘解码**，稳态内存 = meta + 缩略图。
2. **新增关窗弹窗**：有未清理预览缓存时点 X → 弹「关闭程序前需要清空缓存，清空后关闭，请稍后」→ 清空 → 自动关闭。以前直接关窗。test.mode 下跳过弹窗只清空。
3. **预览完成但选中已切换**：缓存目录**保留**（旧实现直接放弃全部结果）。重新选中该条目时命中缓存、秒出缩略图——这是有意改进，非回归。
4. 会话 8 遗留风险兜底：**meta 损坏（有 .complete 但 meta.json 解析失败）** → 预览时捕获 IOException → 删该 key 目录并重建（原先同 key 下会反复报「解析失败」无法恢复）。`listKeys` 扫描时若遇损坏 meta 抛异常，本轮规则 (a)/(c) 删除跳过并 log.warn（损坏目录最终由退出 deleteAll 清除）。

## 撤销路径风险处理（提示词要求说明）
**结论：撤销不会调用 `applyItemParams`/`applyGroupParams`/`applyConfirmedParams`/`applyGlobalParamsTo`**——`onUndoClicked` 的 PARAM_SET/CLEAR_PARAMS/APPLY_GLOBAL 分支是**直接回写** `imageItemParams`/`imageParamsCache` 等字段（已读源码确认），因此在这四个方法里接线不会因撤销被重复触发。但撤销恢复旧参数**本身也是参数变化**（规则 (a) 语义），故在撤销三个分支内**显式**补了 `onParamsChanged(Batch)`（仅 `im == true`），与 forward 路径对称。删除只删磁盘目录，不动内存态（`clearPreviewCache` 照旧由撤销分支自行调用），不破坏撤销的恢复语义；最坏情况是"删了仍有效的缓存"，代价仅下次预览重建，语义安全。

## 关窗处理器的实现方式（含并发协调）
- **挂接**：`initialize()` 阶段 scene 尚不存在（`App.start` 在 `loader.load()` 之后才 `new Scene`/`setScene`），故经 `fileListView.sceneProperty()` → `scene.windowProperty()` 两级监听，window 就绪后 `stage.setOnCloseRequest(this::onWindowCloseRequest)`。
- **流程**：`hasCachedEntries()`（根目录下有任意条目即视为有，含 meta 损坏目录）→ 无则直接放行（不弹窗）；有则 `consume` → 非 test.mode 弹 INFORMATION（文字即需求原文）→ `cancelWorkspaceActivity()`（`requestToken++`/`parseToken++` 置停止标志，在途预览线程看到代次失效会放弃后续工作）→ `previewLoadThread.join(2000)` 等写入结束（超时则接受删除与写入竞争：原子写入方案下最坏是写入失败被吞）→ `onShutdown`（`store.deleteAll()`）→ `shutdownCacheCleared = true` → `stage.close()` 二次触发关窗放行。
- **安全边界**：只删 `PreviewCacheStore.root`（`<java.io.tmpdir>/mht-extractor-preview/`），绝不触碰 tmpdir 整体（P6）。
- **test.mode**：跳过弹窗只清空（防自动化关窗阻塞；实际 test.mode 经 `Platform.exit`+`System.exit` 退出本就不走 closeRequest，此分支为防御性）。
- **写盘后自校验**：预览线程写盘完成后在 FX 线程复核「条目未移除 ∧ 生效图片参数指纹与写盘时一致」（用**模式无关**的 `ParamScope.effectiveImageParams(parentGroup, imageItemParams, imageParamsCache)`，切文本模式不会误删图片缓存）；不符 → 后台线程删刚落盘的目录（覆盖「写盘期间参数/条目变化」与「手工删目录外」的一切竞态窗口）。

## 新发现（未修，留待后续）
1. **§2.6(3) 流式产出未落地**：`extractImages` 仍是全量 `List<ImageData>`，预览落盘期间**瞬时**持有全部全尺寸字节（提取完成后随局部变量回收；稳态 = meta + 缩略图）。C2 按稳态语义验收。若要严格瞬时内存，需会话 10 前后在 `ImageExtractor` 加 sink 式重载（本会话文件集不含该文件）。
2. **强制杀进程留下的「完整」缓存目录**：启动只做 `cleanupOrphans()`（按提示词要求），上一会话 `kill -9` 留下的有 .complete 目录会残留到**本会话结束时**被规则 (d) 清空——若用户本会话从未预览，关窗时仍会弹一次清空提示（提示语"需要清空缓存"语义成立）。若想严格「启动即全新会话」，可在 startupCleanup 改为 deleteAll（一行改动，需拍板）。
3. 输入目录切换是**增量合并**（不清列表），不存在「换目录丢缓存」问题；无新规则缺口。
