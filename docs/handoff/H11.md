## 边界场景（11.10）与并发（11.11）

| 场景 | 结果 | 证据 |
|---|---|---|
| 0 张图片的 MHT | ✅ | `emptyImagesCacheFallsBackToFullPath`：0 图缓存（预览对无图文件的真实产物）→ 未命中 → 全量路径 → SKIPPED 与无缓存一致，缓存保留 |
| 超大 MHT（>50MB） | ✅ | `largeFileOverThresholdCacheHitSkipsRead`：51MB 垃圾字节文件 + 有效缓存 → 命中 SUCCESS、输出=缓存字节（若命中路径读文件/解析必然失败——反证跳过读盘）；`key.size` 只取元数据。50MB 阈值本身只作用于 GUI 预览确认弹窗（MainController:4582），与缓存逻辑无关 |
| 含 Data URI 图片 | ✅ | `dataUriOnlyMhtConsistentWithNoCache`：data-URI-only 文件有/无缓存结果一致（「无图片内容」跳过为既有冻结语义，H10 新发现 2）；`nullSourceIdCacheFallsBackToFullPath`：全 null sourceId 缓存（location-only/广告过滤后 data URI 图的预览产物）→ 未命中 → 输出逐字节一致 |
| 区域限定命中 | ✅ | `regionLimitedCacheHitByteIdentical`：两张 cid 图、区域只含 img001 → 缓存命中 → 输出与无缓存逐字节一致 |

| 中文/空格/特殊字符文件名 | ✅ | `specialCharsAndChineseFileNameCacheHitByteIdentical`：`中文 测试（副本）#1.mht` → key.toDirName 为 64-hex（与字符集无关）→ 命中输出逐字节一致 |
| 同名不同目录 | ✅ | `sameNameDifferentDirsIndependentCaches`：`d1/a.mht` 与 `d2/a.mht` → 不同 toDirName → 提取其一仅删自身缓存，另一个完整保留 |

## 新发现（未修，留待后续）

1. **C8 关窗弹窗仍无自动化覆盖**（实施计划 §九 已知限制 3 延续）：test.mode 跳过弹窗只清空。弹窗的触发条件（`hasCachedEntries()` 含损坏目录）与清空回调已有单测锁定，但「弹窗出现→文案正确→清空后自动关闭」的完整链路需人工点验，建议并入打包电脑 native 验收清单。
2. **GUI 自动化中 C3 的「删除」腿被 C6 掩盖**：`runAutomatedTests` 的序列是「预览 t01 → 图片提取块（规则 b 已删 t01 缓存）→ 生命周期块（参数变化 → 断言 listKeys 空）」，因此 C3 断言通过时缓存已被规则 (b) 先删——该断言对 C3 删除方向是**间接**的（C3 的重建方向「预览 i01 → 恰 1 目录」是真断言）。C3 删除方向由单测 `paramsChangedDeletesMatchingDirsOnly` 等直接锁定，无功能缺陷；若要 GUI 级直证需在 MainController 增补断言（本会话按 R3 未动生产代码）。
3. **自动化运行期间缓存常驻窗口极短**：1 秒轮询真实根只捕获到两次「出现/消失」状态跳变（21:10:59/21:11:02），未及转储内容——预览落盘到规则 (b) 删除间隔约 1–2 秒，符合设计（C6 立即清理）。
4. data-URI-only 文件的「无图片内容」快速跳过仍为阶段 A 冻结语义（H10 新发现 2 延续）：本会话用 `dataUriOnlyMhtConsistentWithNoCache` 锁定「缓存路径与无缓存路径结果一致」，未改变该语义本身。
