
## 三、脚本归一 + 自动探测 + 快速失败（提交 `e22fdf8`）

**修前**：四个脚本各自写死自己的路径，且 native-image 参数被抄了三份。

| 脚本 | 修前的不可用之处 |
|---|---|
| `build-native.cmd` | `BUILD_JAVA_HOME` / `GRAALVM_HOME` = `X:\...`、`MAVEN_HOME=X:\apache-maven-3.9.9`、`OUTPUT_DIR=X:\123\MHTtoEX`；`vcvars64.bat` 指向 `Visual Studio\18` |
| `build-native.ps1` | `$ProjectDir` / `$GraalVMHome` = `Y:\JAVA环境\...`；`VS\18\Community` |
| `run-native-image.bat` | `Y:\...`；`VS\18\Community`；`cd /d Y:\JAVA环境\MHT` |
| `build-native.sh` | 手工拼 `INCLUDE`/`LIB`，写死 MSVC `14.51.36231`、SDK `10.0.28000.0`、`VisualStudioVersion=18.0` |

**修后**：`build-native.cmd` 唯一实现；`.ps1` / `.sh` / `run-native-image.bat` 各 3–25 行，**委托**调用它。
自动探测 JDK / native-image / Maven / 输出目录；MSVC 缺失时**开跑前**就 `exit 20` 并给出修复指引
（原先只 echo 一条 WARNING 就继续，最后死在半路且看不出原因）。去掉 `pause`（会卡住自动化）。

新增 `--prepare-only`：只做 JVM 侧准备（版本 / 打包 / 抽 DLL），**不调用 native-image**
——它也是**本机（无 MSVC）唯一能端到端验证的路径**。

`.gitattributes` 补 `*.bat text eol=crlf`：原先 `*.bat` 落回 `* text=auto eol=lf`，会检出成 LF。

## 四、构建可观测性契约（提交 `8aa72e7`，**本次核心交付**）

需求是"**打包机上构建时，智能体要能实时拿到完整数据流**"。实现方式：

| 新增 | 作用 |
|---|---|
| `native-tee.ps1` | cmd 没有 `tee`。把外部命令（maven / native-image）的输出**实时**同时送到控制台与日志。命令以**文件**传入，避免 native-image 那串带引号参数经历 cmd→PowerShell 的引号地狱 |
| `native-report.ps1` | 产出机器可读报告 |

**每次构建产出三件套**（`<stamp>` = `yyyyMMdd-HHmmss`）：

| 产物 | 位置 |
|---|---|
| 主日志 | `logs/native-build-<stamp>.log` |
| 步骤明细 | `logs/native-build-<stamp>.steps.tsv`（TSV：step / name / begin / end / exit） |
| **报告** | `logs/native-build-<stamp>.report.json` |

报告即**数据流本身**：
`status` / `failedStep` / `gitCommit` → **context**（JDK、native-image、Maven、VS、版本、xmx）
→ **input**（jar 体积 + SHA256）→ **steps**（逐步耗时与退出码）→ **artifacts**（dist 内每个文件的体积 + SHA256）。

> 报告放 `logs/` 而**不是** `dist/`，让 `dist/` 只留交付物（exe + DLL），"整个目录拷走即用"。

**退出码**：`0` 成功 / `1` 其它失败 / **`20` 缺 MSVC**（与 native-image 同码）。
**失败时**打印 `=== FAILURE ===`（失败步 + 退出码 + 日志末 40 行），**仍然产出报告**。

### 实测证据

| 项 | 结果 |
|---|---|
| **实时性** | 构建进行中日志**单调增长**：1180 → 3139 → 6364 → 13239 → 13781 字节 |
| **构建中可读** | `Get-Content` ✅ 全程可读（2954→5585→12259→12950→13358 字符）；`FileStream+FileShare.ReadWrite` ✅；**`File.ReadAllText` ❌** |
| 报告（`--prepare-only`） | `status=PREPARE_ONLY`、`steps=4`（逐步耗时正确）、`artifacts=[]` 为**数组** |
| 报告（失败路径） | `status=FAILED`、`failedStep=2/6 MSVC 预检`、`steps=2`（失败步 `exit=20`）、`artifacts=[]` 数组、input jar 16,039,281 字节 + SHA256 |
| 脚本退出码 | 失败路径实测 **20**（修前恒为 0） |
| 产物扫描（单测） | 造假 dist 两文件 → `artifacts=2`，体积与 SHA256 正确 |

## 五、查出的三个真实缺陷（都已修，都在 CLAUDE.md 留了记录）

1. **脚本退出码恒为 0**：`endlocal` 会丢弃 `setlocal` 内定义的 `RC`，之后 `exit /b %RC%` 已展开为空
   → 脚本化调用完全失效。改为 `endlocal & exit /b %FINAL_RC%`（整行先展开再执行）。

2. 🚨 **PS 5.1 在 LF-only 的 `.ps1` 里会静默丢弃哈希表字面量中「注释行之后」的那个键**——
   不报错、不警告。最小复现：

   ```
   LF 文件   -> keys = x,z      ← y 被吞
   CRLF 文件 -> keys = x,y,z    ← 正确
   ```

   这条**真实导致报告里的 `steps` 字段凭空消失**，排查了数轮（先怀疑解析、再怀疑序列化，
   最后才定位到换行）。而 `.gitattributes` **本就规定 `*.ps1 text eol=crlf`** —— 是新建的文件违反了约定。
   （注：`.claude-work/*.ps1` 目前**全部是 LF-only**，属同类隐患。）

3. 🚨 **日志写锁**：`StreamWriter` 默认共享模式下，**构建进行中其他进程读不了日志**——
   恰好废掉"实时反馈"这个需求本身。改为 `FileStream(..., FileShare.ReadWrite)`。
   同时实测清楚：读方要用 `Get-Content` 或同共享模式，`File.ReadAllText` 不行。

另修：`:say` 传空参数会打出 `ECHO is off.`，改为输出真正的空行。

## 七、在打包机上怎么用

```bat
build-native.cmd --prepare-only   :: 先验环境（不依赖 MSVC，约 12 秒）
build-native.cmd                  :: 完整构建 -> dist\MhtExtractor.exe + 12 个 DLL
```

**智能体实时跟踪**（构建进行中即可用）：

```powershell
Get-Content logs\native-build-*.log -Wait -Tail 50
```

环境变量覆盖（不改脚本）：`BUILD_JAVA_HOME` / `GRAALVM_HOME` / `MAVEN_CMD` / `OUTPUT_DIR` /
`NATIVE_XMX`（默认 4G）/ `VSWHERE` / `LOG_DIR`。
