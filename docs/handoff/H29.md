依赖方向（单向、无环）：

```
BrowserLauncher (门面)
   ├── BrowserDetector   （用什么 exe 打开）
   ├── SourceViewPage    （源码页长什么样）
   └── CdpClient         （在浏览器内部导航 view-source:）
           └── BrowserDetector.decodeConsole （结束挂起实例前解码控制台输出）
```

### 1.1 留在门面的编排点

`openViewSourceNative` **有意留在门面**：它同时调用 `BrowserDetector`（探测/识别）、
`CdpClient`（确保实例 + 打开标签 + 关闭渲染标签）、`SourceViewPage`（回退页生成）——
是三者之间的**编排**，放进门面才符合"门面做编排、其余各司其职"。

### 1.2 搬入 `CdpClient` 的内容

| 分组 | 成员 |
|---|---|
| CDP 端点 | `openTabAndVerify`（PUT 打开标签 + 列表验证）、`checkTab`、`checkTabSlow`、`closeRenderTab` |
| 实例管理 | `ensureCdpInstance`、`probeVersion`、`launchCdpInstance`、`killListenerOnPort` |
| HTTP 客户端 | `httpRequest`（两个重载）、`readResponse`、`readLine`（原生 Socket，native-image 安全） |
| 类型/常量 | `TabState`、`Probe` 枚举；`CDP_PORT`、`CDP_PROFILE_NAME` |

访问性：门面调用的 `openTabAndVerify` / `ensureCdpInstance` / `closeRenderTab` 与
`CDP_PORT` / `CDP_PROFILE_NAME` 放宽为**包级**；其余保持 `private`。

## 二、本步我犯的错（第 4 次同类，但这次教训更具体）

| # | 错误 | 后果 | 修正 |
|---|---|---|---|
| 1 | 用 `findLine('ensureCdpInstance(')` 找**声明** | 匹到 `openViewSourceNative` 里的**调用点**，算出 3 行的假区间 → 脚本 ABORT | 改为**声明锚定**正则（行首必须是修饰符 + 返回类型 + 方法名） |
| 2 | 恢复备份时用了**上一次失败尝试**留下的中间文件 | 行号表与真实文件不匹配，搬错区间 → 生成出 `private static boolean CdpClient.openTabAndVerify(...)` 这种非法声明 | **从 git 恢复**（已提交版本才是可信基线），而不是用临时备份 |
| 3 | CDP 区块起点取成 `closeRenderTab` | 漏搬 `openTabAndVerify`/`checkTab`/`checkTabSlow`（它们在 `closeRenderTab` **之前**） | 起点改为 `openTabAndVerify` |
| 4 | 常量随区块搬走后，门面引用未加限定 | `CDP_PORT` 找不到符号 | 门面加 `CdpClient.CDP_PORT` / `CdpClient.CDP_PROFILE_NAME` |
| 5 | `CdpClient` 缺 `Locale` / `ByteArrayOutputStream` import | 找不到符号 | 补齐 import |

> **本轮真正学到的（已固化为流程）**：
> ① **"找声明"必须用声明锚定的正则**，不能用 `indexOf(名字 + '(')` —— 同名 token 的调用点会先被匹到。
> ② **恢复基线要用 git，不要用临时备份** —— 临时文件可能来自一次失败的中间态，
>    用它当基线会让"行号表"与真实文件不一致，产生**看起来像语法错误、实为搬错位置**的诡异结果。
> ③ **块起点要选"该职责最早的那个成员"**，不能随手挑一个"看起来像开头"的 ——
>    成员在文件里的物理顺序不一定等于逻辑顺序。
> ④ 最终采用**自定位**（脚本运行时用声明锚定 + 花括号配平自己算区间）而非硬编码行号表，
>    这个版本一次成功 —— **以后跨文件搬迁一律这么做**。
