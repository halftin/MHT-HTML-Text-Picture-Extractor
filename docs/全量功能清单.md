## 发现（只记录，不修）

1. **GroupItem / GroupStructure 依赖 JavaFX**：`GroupItem` 用 `StringProperty/BooleanProperty/ObservableList`（GroupItem:19-22），`GroupStructure.restoreStructure` 用 `ObservableList.setAll`（GroupStructure:126）。数据模型层（util 包）混入 JavaFX 类型，换 UI 框架时首当其冲。
2. **PreviewItem 是 MainController 内部类**（MC:228）：GUI 状态（JavaFX 属性）与领域状态（path/sourceFolder/removed/cached*/参数）混合，业务层无法脱离 MC 复用列表模型；`OutputUnitPlanner` 只能靠 `ItemView` 接口抽象（MC:268）绕行。
3. **UndoManager.Record 是"上帝记录"**：10 种类型共用 20 字段构造器（UndoManager:57-112），扩展新撤销类型需重写所有构造调用点（MC 内 10 处 push）。
4. **撤销逻辑全部内联在 MC.onUndoClicked**（MC:3439-3686，约 250 行 switch），与 UI 刷新（refreshAfterListChange/updateInfoArea/updateExtractBanner）交织，无法对撤销语义做纯逻辑测试（现有测试靠 -Dtest.mode GUI 自动化兜底）。
5. **MhtImportPlanner.Scanner 线程受限约定靠注释**（MhtImportPlanner:101"只能被创建它的线程使用"），无运行时防护；nextRound 与 FX 线程 applyImportPlan 跨线程协作靠 Platform.runLater 约定。
6. **I18n 依赖已渗入业务层**：BatchProcessor.reportExtractorWarnings/TextBatchProcessor/ImageBatchProcessor/OutputUnitPlanner/HtmlExportBuilder 均直接调用 I18n.get 拼用户文案（如 BatchProcessor:263），业务层与文案绑定，解耦时需引入警告码/事件替代。
7. **进度回调链 JavaFX 无关但 Task 耦合**：BatchProcessor 的 ProgressCallback 接口本身纯净（BatchProcessor:67），但 MC 侧用 javafx.concurrent.Task 承载（MC:2022），取消信号经 `task::isCancelled`（Supplier<Boolean>）注入——抽象已存在，重构友好。
8. **提取结果回写按路径匹配**（MC.applyExtractResults:1794）：FileResult 以 path 为键回写 PreviewItem，路径重复（同名文件两次导入已去重，但撤销后可再导入）时取 Map 最后一条，语义为"最后写入胜出"。
9. **浏览器查看与预览缓存两套独立缓存体系**：`%TEMP%/mht-extractor-view`（HtmlExportBuilder，7 天保留）与 `%TEMP%/mht-extractor-preview`（PreviewCacheLifecycle，退出清空）并存，无共享清理策略。
10. **AD_KEYWORDS 硬编码**（ImageExtractor），AppConfig 无对应参数（AppConfig:124-125 注释自认），参数化时须同步加入 imageExtractionFingerprint。
11. **createPreviewCell 巨型 cell 工厂**（MC:2211-2724，约 500 行）：行渲染、拖拽手势、三态背景、徽标、缩略图重排全在其中，是 GUI 层最复杂单点。
12. **exerciseAllFeatures/runAutomatedTests 与生产代码同文件**（MC:4972-6064，约 1100 行）：测试/演练逻辑占 MC 近 1/5，且依赖内部状态直接操作，重构时须先剥离。
13. **FileUtils.findMhtFiles 与 MhtImportPlanner 功能重叠**：旧路径（BatchProcessor.collectMhtFiles → FileUtils:25，按修改时间排序）与新导入路径（MhtImportPlanner，按文件名排序）两套收集逻辑并存，排序口径不一致（按修改时间 vs 按文件名）——提取按传入顺序（OutputUnitPlanner paths）时旧口径仅剩兜底用途。
14. **关窗链二次 close 依赖实例状态**：shutdownCacheCleared 标志（MC:376）+ 手动 stage.close()（MC:622），而非消费事件后放行，逻辑脆弱。
15. **MainController 单类 6100+ 行**：UI 装配、导入、拖拽、撤销、预览、提取编排、持久化、演练/测试全部内聚，为本次解耦重构的核心对象。
