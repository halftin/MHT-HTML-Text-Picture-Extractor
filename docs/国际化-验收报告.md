## 二、native 元数据增量（任务 A）

**采集方式**（未手工推断，架构文档 §六）：tracing agent 跑应用自身两次——
`-agentlib:native-image-agent=config-output-dir=target/agent-i18n-out` +
`-Dtest.mode=true`，zh（`-Duser.language=zh -Duser.country=CN`）与 en（`en/US`）各一轮
（每轮 30/30），agent 自动合并两轮结果。采集前临时移走 `logs/gui-state.json`
（其持久化 `locale=zh_CN` 会覆盖 `-Duser.language`），跑完已恢复。

**采集结果与预期差异（重要发现）**：架构文档 §六预期 `ResourceBundle` / `PropertyResourceBundle` /
`Locale` / `ResourceBundle$Control` 反射条目——**实际采集为 0 条**。原因：properties bundle 在 classpath
模式下走 `ResourceBundle.Control.newBundle` 的 `new PropertyResourceBundle(stream)` **直接构造**路径
（无反射）；`ResourceBundle.getBundle` 本身由静态可达性覆盖。真正需要的是**资源条目**（bundle 注册 + glob）。
`ErrorCode` 枚举：**0 条反射条目**（仅经 `I18n.get` 字符串键使用，不经反射/Jackson）。

**合并进 `reachability-metadata.json` 的条目**（合并脚本 `.claude-work/merge-i18n-native-metadata.py`）：

| 类别 | 条目 | 说明 |
|---|---|---|
| reflection ×2 | `sun.text.resources.BreakIteratorResources_en`、`_en_US` | en locale 断词资源类（与既有 zh 条目同构，en 轮实际加载） |
| resources ×1 | `{"bundle": "i18n/messages"}` | **核心**：native-image 注册本应用 bundle（含全部 locale 变体） |
| resources ×7 | `i18n/messages{,_en,_en_US,_zh,_zh_CN,_zh_Hans,_zh_Hans_CN}.properties` | agent 观测到的 bundle 查找（含未命中变体，照既有文件惯例收录） |
| resources ×8 | JavaFX `controls_en{,_US}.properties`、`QuantumMessagesBundle_en{,_US}.properties`（各 module+plain 两态） | en locale 下 JavaFX 内置控件文案（与既有 zh 变体对称） |
| resources ×1 | `META-INF/services/java.util.spi.ResourceBundleControlProvider` | ResourceBundle SPI 探测路径 |
