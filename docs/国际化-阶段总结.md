## 六、一个被实测纠正的架构假设（重要）

**我在架构设计 §六中预期** i18n 需要 `ResourceBundle` / `PropertyResourceBundle` / `Locale` /
`ResourceBundle$Control` 的**反射条目**。

**tracing agent 实测结果：0 条反射条目**。原因：classpath 模式下 properties bundle 走
`ResourceBundle.Control.newBundle` → `new PropertyResourceBundle(stream)` 的**直接构造**路径（无反射）。

**真正需要的是资源注册**：

```json
{"bundle": "i18n/messages"}                                    // 核心：注册 bundle 全部变体
{"glob": "i18n/messages_{,_en,_en_US,_zh,_zh_CN,_zh_Hans,_zh_Hans_CN}.properties"}
{"glob": "com/sun/javafx/scene/control/skin/resources/controls_en{,_US}.properties"}
{"glob": "META-INF/services/java.util.spi.ResourceBundleControlProvider"}
```

这正是"**不要手工推断元数据，要用 agent 采集**"这条纪律的价值——我的推断错了一半方向。
